# Development Plan — v0.13 (WIP)

## Headline

**Epic — Refound kiso as a B2B knowledge-work agent substrate
built around always-on structured audit. Ship the audit query
interface as the public-facing differentiator; collapse the
LLM-call pipeline to architect + editor without sacrificing
`validate_plan` or the install state machine; reach competitive
parity on efficiency.**

Origin: [VISION.md](../VISION.md) (four invariants — robust,
deterministic, auditable, efficient) and
[STRATEGY.md](../STRATEGY.md) (three structural differentiators
vs Forge/Goose; four success criteria; audit query interface as
the v0.13 headline). Supersedes the prior "preserve-then-optimize"
draft, which was shaped around closing a benchmark gap that
STRATEGY explicitly declares out of scope.

## Mapping — pillars to invariants and success criteria

| Phase | Pillar | VISION invariant | STRATEGY success criterion |
|---|---|---|---|
| A | Audit (M1672-M1674) | III. Auditability | C3 audit query interface |
| B | Pipeline collapse (M1675-M1678) | II. Determinism | C1 cerase Goose-swap precondition |
| C | Efficiency (M1679-M1682) | IV. Efficiency | competitive parity |
| D | Knowledge-work benchmark (deferred v0.14) | — | C2 replace Terminal-Bench/SWE-bench |
| E | Cerase pilot (deferred v0.14) | — | C1 swap on Document Q&A template |

Robustness (invariant I) is preserved transversally: `validate_plan`,
install state machine, circular replan detector, deterministic
safety-pattern redaction, cross-session knowledge are all
non-negotiable and explicitly out of scope of any removal.

## Anima preserved — what v0.13 does NOT touch

Audit of `kiso/brain/planner.py:404+`, `kiso/worker/loop.py:1640-1711`,
`kiso/brain/common.py`, `kiso/brain/reviewer.py`. The following
are explicitly preserved (and in some cases reinforced):

1. **`validate_plan` 22+ structural checks**. Including
   `needs_install` coherence, `install_approved` literal exec form
   (M1627), artifact-creation rule (M1628), codegen guardrail
   (M1233). Pipeline collapse extends `validate_plan`, never
   shrinks it.
2. **Install state machine** (`needs_install` → user approves →
   exec literal). State-machine authority, not LLM judge.
3. **Circular replan detector with self-directed bypass** (M1662).
4. **Cross-session knowledge** (F23): facts, curator, consolidator.
5. **Docker sandbox**.
6. **MCP / skills / connectors taxonomy**.
7. **Deterministic safety-pattern redaction**.
8. **kb_answer / msg-only / awaits_input plan shapes**.

Anything in this list removed or weakened during v0.13 is a
regression, not a refactor.

## Phase A — Audit headline

The differentiator vs Forge (JSONL logs) and Goose (session-store
introspection). Ship first, before the refactor: forensics
visibility during the refactor itself is the safest path. By the
end of Phase A, every kiso decision in any test session is
queryable from logs alone.

### M1672 — Always-on structured audit store

Replace the opt-in `KISO_DUMP_PLANNER_PROMPT` env var with a
default-on structured store. Every LLM call, tool dispatch, rule
decision, and state transition is written to a per-session SQLite
file (`KISO_DIR/sessions/<id>/audit.db`) with a versioned schema.

The store is the canonical source for reconstructing turn-level
decisions; existing free-text logs become a debug aid only.

- [ ] Schema design: tables for `llm_call`, `tool_dispatch`,
      `rule_decision`, `state_transition`, `turn`, indexed by
      session + turn + timestamp.
- [ ] Write path: instrument `kiso/llm.py:114` (LLM calls),
      `kiso/worker/loop.py` (tool dispatch, state transitions),
      `kiso/brain/planner.py:404+` (rule decisions inside
      `validate_plan`).
- [ ] Backwards-compat: `KISO_DUMP_PLANNER_PROMPT` still works
      (forwards to store + dumps text), can be deprecated in a
      later milestone.
- [ ] Storage budget: per-session size cap with rotation policy
      (deferred to the policy milestone if needed).
- [ ] Regression: existing functional tests pass with audit on
      by default.

### M1673 — Audit query CLI + API

`kiso audit explain --session S --turn N` reconstructs the chain
of decisions for that turn: LLM calls (with cached input ref +
output ref), tool dispatches (with args + result), rule decisions
(with which check fired and why), state transitions. Output is
human-readable (default) or JSON (machine-readable, for
downstream tooling).

Companion API surface exposed to a downstream operator without
requiring kiso source navigation.

- [ ] CLI subcommand `kiso audit explain` with flags `--session`,
      `--turn`, `--format {text,json}`, `--depth {summary,full}`.
- [ ] `kiso audit list --session S` to enumerate turns.
- [ ] `kiso audit search` for content-based lookup (find sessions
      where rule X fired, where tool Y returned error Z).
- [ ] Python API mirroring the CLI for downstream embedding
      (cerase, future consumers).
- [ ] Acceptance: a fresh operator can answer "why did the agent
      do X at turn N" from logs alone, given the CLI docs only.

### M1674 — Audit contract documentation

`docs/audit.md` defines: what is logged, what is not, why,
schema versioning, forensics workflow (post-incident), how to
extend the schema for consumer-specific decisions.

- [ ] What's logged enumerated explicitly (table by table).
- [ ] What's NOT logged (privacy scope: do we log user message
      content? raw tool output if large?) and why.
- [ ] Schema version stability commitment.
- [ ] Forensics workflow example: induce a failure, walk through
      the query that diagnoses it.
- [ ] Linked from CLAUDE.md, README, and `VISION.md`.

## Phase B — Pipeline collapse

The architecture refactor toward architect + editor (2 LLM calls
on the common turn). Preserves every deterministic guardrail from
v0.12; reduces LLM round-trips that exist for the pipeline's sake,
not the domain's sake.

### M1675 — Merge worker translator into planner

Today the planner emits natural-language `detail` and the worker
translator calls an LLM to render it as shell. Move the literal
emission into the planner. `validate_plan` is extended to verify
the shell literal (it already does for `kiso mcp install --from-url`
under M1627 — natural extension).

Removes N LLM calls per turn (one per exec task). Removes the
M1627-class bug structurally (no translation step where the
literal can drift).

- [ ] Planner schema: `exec` task takes a literal `command`
      field, not free-text `detail`.
- [ ] `validate_plan` extension: shell literal format checks,
      forbidden patterns (no `rm -rf /`, etc. — leverage existing
      safety-pattern redaction infrastructure).
- [ ] Worker translator role deleted; worker dispatches the
      literal directly.
- [ ] Audit: rule decisions on shell-literal validation logged
      to M1672 store.
- [ ] Regression: existing exec-shaped tests pass; safety
      patterns still enforced.

### M1676 — Reviewer end-of-turn, not per-task

One reviewer LLM call per turn (sees all tool outputs of the
turn) instead of N (one per task). Safety pattern enforcement,
learning curation, stuck detection all preserved with full-turn
context.

Reviewer per-task remains available behind a config flag for
specialized recipes that need per-task verification, but is not
the default.

- [ ] Reviewer invocation moved to end-of-turn boundary in
      `kiso/worker/loop.py`.
- [ ] Reviewer prompt updated to accept turn-level context (list
      of tasks + outputs) instead of single-task context.
- [ ] Safety pattern redaction stays per-task (deterministic,
      not LLM).
- [ ] Config flag `reviewer.scope = {turn, task}` with default
      `turn`.
- [ ] Audit: reviewer decision logged once per turn, with
      reference to all tasks observed.
- [ ] Regression: M1652 safety-violation enforcement still
      catches.

### M1677 — Briefer deterministic by default, LLM fallback

Cache aggressive on `(consumer_role, pool-hash, intent-tag)`;
rule-based ranking (BM25 / embedding) on catalog MCP / skills as
default; LLM briefer fallback only on cache miss or ambiguity
beyond a confidence threshold.

Removes the briefer LLM call on the common path while preserving
the decision (briefer's job is filtering, not retrieval, but the
filtering decision can be cached and deterministic for the bulk
of cases).

- [ ] Cache layer for briefer output keyed by structured input
      hash.
- [ ] Deterministic ranking module for MCP / skill / module
      selection (BM25 baseline, embedding optional).
- [ ] Ambiguity detector to trigger LLM fallback (e.g., top-K
      candidates with similar scores → LLM tiebreaker).
- [ ] Backwards-compat: existing briefer call path stays as the
      fallback implementation.
- [ ] Audit: briefer decisions (deterministic or LLM) logged
      with which path was taken and why.

### M1678 — `planner.md` slim (Decision Tree to tool schemas)

Target ≤ 8 KB (from 27.6 KB). The Decision Tree branches become
the schema of a structured `propose_plan` tool with native
function calling; `validate_plan` remains as post-hoc structural
check.

Guardrail rules stay verbatim where they reference invariants
checked by `validate_plan`. Prose (examples, deprecated
`plugin_install` hints, stylistic guidance) goes.

- [ ] Inventory: every `<!-- MODULE: -->` block measured and
      classified GUARDRAIL / SCHEMA-CANDIDATE / PROSE.
- [ ] Schema design for `propose_plan` tool covering the 8
      Decision Tree branches.
- [ ] `validate_plan` covers post-hoc what was previously prose-
      enforced; new checks added where needed.
- [ ] Rewrite `planner.md` lean.
- [ ] CI test: `planner.md` size budget ≤ 8192 bytes enforced.
- [ ] Live tier regression sweep.

## Phase C — Efficiency

Competitive parity with Forge / Goose. Not differentiation, but
deployment requirement: an inefficient kiso is a research project
(per VISION invariant IV).

### M1679 — Prompt caching first-class

`cache_control: {"type": "ephemeral"}` headers via OpenRouter on
static prefixes (planner system prompt, briefer fallback prompt,
reviewer system prompt). Mandatory on static prefixes per VISION
invariant II.

- [ ] `kiso/llm.py` request assembly emits `cache_control`
      blocks at the breakpoint between static and dynamic
      sections.
- [ ] Per-role identification of the static-vs-dynamic boundary.
- [ ] Cache-hit metric surfaced in OpenRouter response, logged
      to audit store.
- [ ] Acceptance: ≥80% cache hit rate on planner system prompt
      after turn 1, measurable from the audit store.

### M1680 — Parallel tool dispatch (planner emits `parallel_group`)

Infrastructure already exists in `kiso/worker/loop.py:1015-1042`
(`_build_execution_batches`) and dispatches via `asyncio.gather()`
at line 1189. Missing piece: the planner never emits `group: N`.

- [ ] `parallel_group` field added to plan schema, validated by
      `validate_plan` (no group across heterogeneous task types,
      no group on `replan`).
- [ ] Decision Tree rule (in the new `propose_plan` schema from
      M1678): tasks with no shared output reference and no
      sequential msg dependency share a group id.
- [ ] Acceptance: a synthetic 3-independent-read plan runs in
      `max(t1, t2, t3)` wall-clock, not `t1+t2+t3`.

### M1681 — Progressive context shedding (Goose pattern, audit-preserving)

On `ContextLengthExceeded` from the provider, retry-shed-retry
in-band. Middle-out removal of tool-response messages at growing
percentages (`[0, 10, 20, 50, 100]`, Goose `context_mgmt`).

**Audit-preserving constraint**: shed messages are removed from
the LLM context but the audit store retains them in full. Loss
of LLM visibility, not loss of audit trail.

- [ ] Wire retry-shed-retry path gated on `ContextLengthExceeded`.
- [ ] Middle-out removal at staged percentages.
- [ ] Proactive cutoff: trigger summary batch after N tool calls
      (Goose `compute_tool_call_cutoff` scaled to context limit ×
      threshold).
- [ ] Audit store retention is independent of LLM context shedding.

### M1682 — Doom-loop tool-signature detector (Forge pattern)

Complementary to kiso's existing replan-level circular detector
(`kiso/worker/loop.py:1640-1711`). Forge detects loops at the
tool-call level: `(tool_name, args)` signature repeated ≥3 times
consecutively → inject a persuasive `<system_reminder>`. Not
blocking.

- [ ] Signature extraction over the last K exec/mcp tasks in the
      current session.
- [ ] Pattern detector: identical-consecutive and cycle-of-length-L.
- [ ] Inject system reminder; do not interrupt; existing
      `validate_plan` and circular replan detector keep their
      authority.
- [ ] Audit: signature-match decisions logged.
- [ ] Regression: synthetic 3× repeating tool call triggers
      reminder; legitimate self-directed pipeline does not.

## Carry-over

### M1664 — `test_search_synthesize_publish` regression — closed as obsoleted

Carried over from v0.12. The bug was structurally caused by the
worker-translator-on-validator-retry code path: planner emitted
`[mcp(search), msg]` → validator rejected → retry context said
"add an exec task that writes the file" → planner dropped the
mcp instead of adding exec.

Under v0.13 the code path disappears. M1675 (merge worker
translator into planner) eliminates the natural-language `detail`
that the worker translator re-interpreted on retry. M1678
(planner.md slim → Decision Tree as tool schema) eliminates the
prose-based validator hint that the planner over-corrected on.
The bug class is removed by construction.

**Status**: closed-by-design. No active fix. Document the
rationale and add a regression test in M1675 that exercises the
exact failure shape (the test goal: a search-then-write plan that
must keep both the search and the exec) to lock the resolution.

- [ ] M1675 includes a regression test reproducing the M1664
      failure shape; no separate fix needed here.

## Open questions

- Q1: M1672 audit store schema versioning — semver or numeric?
  Cerase will read this schema; commitment matters.
- Q2: M1677 deterministic briefer — embedding model choice
  (local vs API). Local sentence-transformers is the default
  guess; cost/latency vs accuracy worth measuring.
- Q3: M1678 ≤ 8 KB target — achievable? An honest re-audit may
  land at 9-10 KB; lock the budget after the first inventory
  pass, not before.
- Q4: M1680 parallel groups — does it interact correctly with
  the circular replan detector when the parallel branches each
  trigger their own replan? Audit pass before shipping.

## Roadmap continues (target v0.14)

The two remaining phases from STRATEGY are deferred to v0.14,
not because they're optional, but because they depend on Phase A
+ B being stable:

- **Phase D — Knowledge-work benchmark suite** (replaces M1669).
  Document Q&A (recall/precision), summary faithfulness,
  structured extraction F1, email-tone classification. Public
  numbers published with audit-trail samples (concrete demo of
  invariant III).
- **Phase E — Cerase pilot**. Document Q&A agent template
  implemented on kiso-run/core with feature parity vs the current
  Goose-based `cerase-agent-<id>` (`cerase/architecture.md` §3.1).
  Cerase appliance integration POC: kiso-run/core as alternative
  runtime in a test appliance, validating that the swap is
  feasible without massive refactor on cerase side.

When v0.13 approaches closure (Phase C complete + acceptance
criteria met), open `devplan/v0.14-wip.md` and migrate these
two phases.

## Out of scope (explicit, by choice)

- **Sub-agent / context compressor** (Goose `subagent_system.md`).
  Tracked as future stretch. Not strategically urgent until a
  consumer surfaces the need.
- **Multi-provider abstraction** (move off OpenRouter monolith).
  OpenRouter covers; no driver to fragment.
- **LLM-based permission judge** (Goose pattern). STRATEGY
  explicitly states state-machine consent over LLM judges.
- **Sandbox change** (Docker → git-worktree). Neutral change,
  out of scope.
- **M1669 Terminal-Bench / SWE-bench follow-ups**. Replaced by
  Phase D in v0.14.
